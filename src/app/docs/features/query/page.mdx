# Querying Your Data

Humanlog features a query engine that allows you to query your data in a declarative manner. The language is called [Humanlog Query Language](/docs/reference). It's a pipeline-based language where you define a series of operations to apply to your data. Read the reference for detailed information. Or keep reading here for a high level overview of how the query feature works and example usages.

## Basic Usage

You can run queries in two ways: via the CLI or the UI.

### Querying Via the UI

If Humanlog is running on your machine, a green dot will be visible next to the datasource selection dropdown on the website.

<img src="/images/docs/features/query/selecting-source.png" width="80%" />

Selecting it will open the query page for this data source.

<img src="/images/docs/features/query/selecting-localhost.png" width="80%" />

The query tab is empty by default.

<img src="/images/docs/features/query/empty-query-tab.png" width="80%" />

To execute a query, first write a query in the query editor area and then either press `Cmd+Enter` or click the "Run" button.

<img src="/images/docs/features/query/query-editor-run-query.png" width="80%" />

<Note>
  Otherwise, you can navigate to the `localhost` query page directly at [localhost/query](/localhost/query).
</Note>

### Querying Via the CLI

Querying via the CLI is mostly a helper to open the UI with a query already set up.

```bash
humanlog query 'filter true | take 10'
```

Which will open the UI with that executes this query and displays its result.

<img src="/images/docs/features/query/query-tab.png" width="80%" />

## Discovering Symbols In Scope

Opening the query library nav bar to see the symbols in scope.

<img src="/images/docs/features/query/query-library-button.png" width="80%" />

The list of symbols shown in the **Symbols List** tab represents key-values that are found in your data set.

<img src="/images/docs/features/query/list-symbols.png" width="80%" />

You can click on a symbol to add it to your query.

<img src="/images/docs/features/query/add-symbol.png" width="80%" />

Otherwise, you can type it out. The rules for refering to arbitrary symbols are:

- If the symbol contains only letters, numbers and underscores, you can refer to it as-is.
- Otherwise, you must refer to it as an index expression, using single or double quote strings like `["my symbol.name!"]` or `['my symbol.name!']`.

Example:

```kusto
// `request_id` is a symbol found in the key-values of your logs
filter request_id == "2937400f-b5c5-426f-b07a-4c7723ff6740"

// `build.Commit` is a symbol found in the key-values of your logs
// it contains a `.` so it must be escaped.
filter ['build.Commit'] == "d31fade"
```

## Query Results

The query result area is where you can see the results of your query. Depending on the type of data you're querying, the results will be displayed in different ways. The datatype of the data is detected automatically and the query engine will attempt to render it in a useful manner. In many cases, you can change the theme of the result to better suit your needs. See the [themes](/docs/features/themes) section for more information.

### Logs

When querying logs data, the results will be displayed in prettified form using the signature display format of `humanlog`. This is the same format that `humanlog` uses when ingesting logs, and it looks like this:

<img src="/images/docs/features/query/log-results-single-session.png" width="80%" />

By default, the query engine will group logs by session. This is to ensure that logs are shown in an order that makes sense based on the source of where they were emitted. See the logging](/docs/concepts/logging) section for more information about ordering of logs.

<img src="/images/docs/features/query/log-results-many-session.png" width="80%" />

You can disable this behavior by turning off the "Split By Session" toggle.

If you don't want to see prettified results, you can turn off the "Pretty" toggle to see the logs in their raw form, as they were ingested.

<img src="/images/docs/features/query/log-results-raw-mode.png" width="80%" />

You can hover over a log to see its metadata. Depending on where you hover, you will see different things. Hovering over the timestamp, level or message will let you see the core information about the log line such as the event ID, timestamp, level, message.

<img src="/images/docs/features/query/log-results-hover-header.png" width="80%" />

You can click on the tooltip buttons to help further filter down the results. Doing so will update your query to add a `filter` clause.

<img src="/images/docs/features/query/log-results-hover-click.gif" width="80%" />

You can hover over a key-value to see its value, its type and then click on premade filters to add to your query.

<img src="/images/docs/features/query/log-results-hover-key-value.png" width="80%" />

Sometimes log lines, even prettified, can get quite long. In this cases, you may want to split the log lines in a vertical manner. Click on the "Toggle section line breaks in log" button to activate this mode.

<img src="/images/docs/features/query/log-results-vertical-split-button.png" width="80%" />

This shows your logs with each key values split on its own line. Return to the horizontal layout by clicking on the "Toggle section line breaks in log" button again.

<img src="/images/docs/features/query/log-results-horizontal-split-button.png" width="80%" />

### Spans

Query spans by specifying the `traces` datatype at the start of your query.

```kusto
traces | take 10
```

This will take 10 spans from your tracing data and display them in span-mode.

<img src="/images/docs/features/query/span-results-overview.png" width="80%" />

If you want to see more details about the span, such as its resource attributes or span attributes, click on the expand button.

<img src="/images/docs/features/query/span-results-expand-span.png" width="80%" />

You can hover over a span to see its metadata. Clicking on the tooltip buttons will let you add premade filters to your query.

<img src="/images/docs/features/query/span-results-hover-tooltip.png" width="80%" />

Otherwise clicking on the span name or trace ID will open a page that shows the span in its trace.

<img src="/images/docs/features/query/span-results-click-span.png" width="80%" />

This page lets you see the span within the context of its trace, where all spans are shown in a waterfall layout. You can view details about the trace.

<img src="/images/docs/features/query/trace-waterfall.png" width="80%" />
