# HumanlogQL

This document describes the operators and functions available in the query language of humanlog.

## Symbols

The following symbols are usable at the begining of a query. These will change as you change the projections or aggregate log events.

### Symbol: `machine`

> is a `scalar:i64`

The ID of the machine during which events were ingested.

This is guaranteed to always exist.

Machine IDs are unique within an environment.

### Symbol: `session`

> is a `scalar:i64`

The ID of the session during which events were ingested.

This is guaranteed to always exist.

Session IDs are _not_ globally unique, nor are they globally ordered. They are only unique within a `machine`, unless the ingestor forcibly specified the session ID and caused a collision.

In some case, the session ID will be defined by the ingesting server and will be unique per machine. If derived from the ingestor, they often are the unix-nano timestamp when the ingestion for the session stream started. If two sessions were to start in the same nanosecond on the same machine, or if the machine has lower resolution timestamps (say milliseconds), they might share the same session ID. This is assumed to not occur.

### Symbol: `event`

> is a `scalar:i64`

The ID of the log event.

This is guaranteed to always exist.

Event IDs are _not_ globally unique, nor are they globally ordered. They are only unique and ordered within a `(machine, session)` tuple. A log event can be uniquely identified, and ordered, using the `(machine, session, event)` tuple.

### Symbol: `parsed_at`

> is a `scalar:ts`

Timestamp when the log event was parsed.

This is guaranteed to always exist.

This is not the time recorded the log event. For example, if you ingest old logs with timestamps in 2014, the `parsed_at` will match today, but `ts` will be in 2014.

### Symbol: `raw`

> is a `scalar:str`

The raw log event as it was parsed.

This is guaranteed to always exist.

Queries against this will be slower than those against parsed structured data.

### Symbol: `ts`

> is a `scalar:ts`

Timestamp detected in the log event. These are detected according to the parsing rules specified in the configuration.

### Symbol: `msg`

> is a `scalar:str`

Message detected in the log event. These are detected according to the parsing rules specified in the configuration.

### Symbol: `lvl`

> is a `scalar:str`

Level detected in the log event. These are detected according to the parsing rules specified in the configuration.

### Symbol: `kv`

> is a `map:{key:{scalar:str}  value:{scalar:unknown}}`

Key-values found in structured logs. If they respect the [a-Z0-9]+ regexp, you can simply refer to them. Otherwise you can refer to them via the `['my.nested.value']` notation, using either single or double quoted strings.

## Scalar Operators

### scalar operator: `!`

Negation of booleans.

#### Examples

##### Example: `!` logical negation

Given these logs:

```ndjson
{"ts":"2006-01-02T15:04:06.001", "lvl": "error", "msg":"log1", "source": {"func":"hello"}}
{"ts":"2006-01-02T15:04:06.002", "lvl": "error", "msg":"log2"}
{"ts":"2006-01-02T15:04:06.002", "lvl": "error", "msg":"log3", "source": {"func":"Blablablb"}}
{"ts":"2006-01-02T15:04:06.002", "lvl": "error", "msg":"log3", "source": {"func":"blablablB"}}
```

Applying this query:

```kusto
project value = !(len(['source.func']) > 5)
```

Produces the output:

| value (`scalar:bool`) |
| --------------------- |
| `true`                |
| `null`                |
| `false`               |
| `false`               |

### scalar operator: `!=`

Returns true if the two sides are unequal. False otherwise. Both operands must be of the same type, or an error will be returned.

For strings, case-sensitive unequality is performed. Use `!~` for case-insensitive inequality.

#### Examples

##### Example: `reuse of extended named-column`

Given these logs:

```ndjson
{"ts":"2006-01-02T15:04:06.001", "lvl": "error", "msg":"log1","source":{"function":"my_func"}}
{"ts":"2006-01-02T15:04:06.002", "lvl": "error", "msg":"log2"}
{"ts":"2006-01-02T15:04:06.002", "lvl": "error", "msg":"log3","source":{"function":"my_other_func"}}
{"ts":"2006-01-02T15:04:06.003", "lvl": "error", "msg":"log4"}
```

Applying this query:

```kusto
filter ['source.function'] != "" | extend func_name=['source.function'] | take 10 | extend world=strcat(func_name, " is a function")
```

Produces the output:

| machine (`scalar:i64`) | session (`scalar:i64`) | event (`scalar:i64`) | parsed_at (`scalar:ts`) | raw (`scalar:str`)                                                                                                         | ts (`scalar:ts`)       | lvl (`scalar:str`) | msg (`scalar:str`) | kv (`scalar:unknown`) | func_name (`scalar:str`) | world (`scalar:str`) |
| ---------------------- | ---------------------- | -------------------- | ----------------------- | -------------------------------------------------------------------------------------------------------------------------- | ---------------------- | ------------------ | ------------------ | --------------------- | ------------------------ | -------------------- |
| `1`                    | `1`                    | `1`                  | `2006-01-02T15:04:06Z`  | `"{\"ts\":\"2006-01-02T15:04:06.001\", \"lvl\": \"error\", \"msg\":\"log1\",\"source\":{\"function\":\"my_func\"}}"`       | `2006-01-02T15:04:06Z` | `"error"`          | `"log1"`           | `{}`                  | `"my_func"`              | `"my_func"`          |
| `1`                    | `1`                    | `3`                  | `2006-01-02T15:04:06Z`  | `"{\"ts\":\"2006-01-02T15:04:06.002\", \"lvl\": \"error\", \"msg\":\"log3\",\"source\":{\"function\":\"my_other_func\"}}"` | `2006-01-02T15:04:06Z` | `"error"`          | `"log3"`           | `{}`                  | `"my_other_func"`        | `"my_other_func"`    |

##### Example: `filter key value`

Given these logs:

```ndjson
{"ts":"2006-01-02T15:04:06.001", "lvl": "error", "msg":"log1", "source":{"function": "blablabla1"}}
{"ts":"2006-01-02T15:04:06.002", "lvl": "error", "msg":"log2", "source":{"function": "blablabla2"}}
{"ts":"2006-01-02T15:04:06.003", "lvl": "error", "msg":"log3", "source":{"function": "blablabla3"}}
{"ts":"2006-01-02T15:04:06.004", "lvl": "error", "msg":"log4"}
```

Applying this query:

```kusto
filter ['source.function'] != "" | project hello=['source.function']
```

Produces the output:

| hello (`scalar:str`) |
| -------------------- |
| `"blablabla1"`       |
| `"blablabla2"`       |
| `"blablabla3"`       |

### scalar operator: `!contains`

(_not_ case-sensitive) Returns true if the left-hand-side string does not contain the string in the right-hand-side. Slower than `!contains_cs`.

#### Examples

##### Example: `string not contains case-insensitive`

Given these logs:

```ndjson

{"ts":"2006-01-02T15:04:06.002", "lvl": "error", "msg":"log2"}
{"ts":"2006-01-02T15:04:06.002", "lvl": "error", "msg":"log3", "source": {"func":"Blablabla"}}
```

Applying this query:

```kusto
filter ['source.func'] !contains "blabl"
```

Produces the output:

```ndjson

```

### scalar operator: `%`

Modulo of the operands. Both must be i64 (integers).

#### Examples

##### Example: `modulo`

Given these logs:

```ndjson
{"ts":"2006-01-02T15:04:06.001", "lvl": "error", "msg":"log1","source":{"line": 1}}
{"ts":"2006-01-02T15:04:06.002", "lvl": "error", "msg":"log2"}

{"ts":"2006-01-02T15:04:06.003", "lvl": "error", "msg":"log4"}
{"ts":"2006-01-02T15:04:06.003", "lvl": "error", "msg":"log5","source":{"line": 3}}
```

Applying this query:

```kusto
project hello=['source.line'] % 2
```

Produces the output:

| hello (`scalar:i64`) |
| -------------------- |
| `1`                  |
| `null`               |
| `0`                  |
| `null`               |
| `1`                  |
